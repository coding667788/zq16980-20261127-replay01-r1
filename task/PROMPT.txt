内部审阅工具会把若干标志位交给规则引擎，再向接收方返回一组允许显示的状态码。我们需要在上线前检查状态码是否间接泄露了受保护的布尔标志。请从空仓库实现 veilresponse，输入是纯合成 JSON，包含至多 24 个布尔字段、表达合法记录的布尔约束、接收方可见字段，以及依次执行的状态码规则。每条规则只有布尔表达式和固定状态码，命中第一条即返回，未命中返回统一默认码。字段的公开范围因接收方而异。另有明确允许披露的派生事实，由布尔表达式定义。

对每个接收方，判断任意两条合法记录在公开字段和获准披露的派生事实完全相同时，返回码是否一定相同。检查默认分支、共享子表达式及无可行赋值的规则。发现差异时给出字段序的字典序最小记录对，记录对内部也按字典序排列。合规模型要支持空的合法记录集合。修复操作只能把指定返回码归并到一个通用码，每个码有一次性成本，默认码也可标为可选；求覆盖所有接收方的最小成本归并集合，同成本按排序后的码列表决胜，无法修复时给出所有候选都归并后仍冲突的证据。审计和修复均须复核原始合法约束；完整实例不能先枚举 2^24 条记录再构造二次方个记录对。

在 Windows 上用 Python 3.12 标准库实现 audit CASE 和 repair CASE 两个 JSON CLI。交付 README、合成样例、unittest，以及 8 个字段以内的独立穷举参照。
